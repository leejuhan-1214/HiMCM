# BeeLab — 꿀벌 군집과 수분을 이해하는 가상 생태계

[2022 HiMCM Problem A: *The Need for Bees (and not just for honey)*](https://www.contest.comap.org/highschool/contests/himcm/2022_Problems/2022_HiMCM_Problem_A.pdf)를 풀기 위한 모델·시뮬레이터입니다. 목표는 **한 벌통의 개체수가 왜 변하는지** 일별로 설명하고, 그 군집이 **20에이커 작물의 개화기에 충분한 방문을 제공하는지** 검토하는 것입니다. 3D 자연환경은 날씨·지형·꽃·먹이·벌의 연결을 탐색하는 창이며, 최종 대회 제출물인 수학적 설명과 1페이지 비전문가 자료를 대체하지 않습니다.

## 우리가 풀려는 네 가지 질문

| 대회 요구 | 이 프로젝트에서 할 일 | 현재 상태 |
|---|---|---|
| ① 한 군집의 시간별 크기 | 단일 벌통의 알·유충/번데기·내근벌·채집벌을 하루씩 추적하고 계절 변화를 설명 | 일별 모델·연간 그래프 구현 |
| ② 무엇이 군집 크기를 좌우하나 | 수명, 산란, 수정란 비율, 발달 생존율 등의 민감도를 **같은 변화폭과 같은 출력 지표**로 비교 | 8개 변수의 국소 민감도·시나리오 범위 구현; 상호작용 검토는 추가 과제 |
| ③ 20에이커에 벌통이 몇 개 필요한가 | 약 81,000 m²의 개화기 꽃 방문 수요를 한 벌통의 날짜별 채집 능력과 비교 | 방문량 기준의 하한·가장 부족한 날 기준 계산 구현; 작물·지역 실측 검증 필요 |
| ④ 비전문가에게 어떻게 설명하나 | 가정, 핵심 결과, 생태계 연결과 불확실성을 1페이지 블로그/인포그래픽으로 전달 | 인쇄 가능한 웹 화면 구현; 최종 원고·그림 검토 필요 |

대회 제출용으로는 **요약시트·목차·참고문헌을 포함한 25페이지 이내 PDF**를 별도로 완성해야 합니다. 웹사이트가 작동한다는 사실만으로 보고서나 결론이 완성된 것은 아닙니다.

## 핵심 모델: 한 벌통, 하루 단위

계산 대상은 여러 벌통을 합친 군집이 아니라 **여왕이 있는 벌통 하나**입니다. 기본 모델은 일별 연령 코호트로 다음 흐름을 추적합니다.

```text
여왕의 산란 → 알 E (약 3일) → 유충·번데기 B (약 18일)
           → 내근벌 H → 채집벌 F → 사망
       └── 미수정란에서 나온 수벌은 별도 경로로 추적
```

산란량은 계절 곡선과 내근벌의 양육 능력에 따라 달라집니다. 알·유충 단계에는 생존확률을 적용하고, 내근벌에서 채집벌로의 이동은 **성충 나이와 기존 채집벌 비율**을 함께 반영합니다. 성수기에는 채집 위험이 커지고, 겨울에는 산란·활동·신규 채집 전환이 줄어듭니다. 수벌은 별도로 계산하지만 여왕 교체는 모델링하지 않습니다. 모델의 개체수는 개별 벌을 모두 생성한 결과가 아니라 **기대 개체수**이므로 소수가 나올 수 있습니다.

초기조건을 덜 임의적으로 만들기 위해 기본적으로 2년을 예열하고 다음 1년을 분석합니다. 예열이 수렴을 보장하지 않으므로 연도 간 차이 진단도 확인합니다. 정확한 갱신 순서, 파라미터 기본값, 보존식과 출처는 [METHODOLOGY.md](./METHODOLOGY.md)에 있습니다.

### 자연환경이 군집에 영향을 주는 경로

```text
계절·전선·소나기·지형·물 접근성
              ↓
구역별 비/눈 → 토양 수분 → 작물·야생 식생의 꽃 자원
              ↓
날씨와 거리 때문에 달라지는 비행·채집량
              ↓
벌통의 상대적 꽃꿀·꽃가루 저장량
              ↓
산란 유지·유충 생존·성충 사망 → 다음 날의 군집·수분 능력
```

3D 세계는 이 **날짜별 인과 연결**을 탐색하도록 만들었습니다. 비가 특정 지역에만 오는 이유는 고정 시드로 생성한 이동 전선과 국지 소나기의 위치·폭, 구역별 수증기와 지형 상승이 다르기 때문입니다. 영하 강수는 눈으로 쌓이고 녹은 물은 토양으로 들어갑니다. 비의 효과는 그날의 비행 제한뿐 아니라 며칠 뒤의 꽃과 먹이에도 나타날 수 있습니다. 지역을 선택하면 그날의 강수 원인과 토양 상태를 볼 수 있습니다.

이것은 **실제 지역의 기상 관측이나 수치예보가 아닙니다.** 전선 발생일, 지형, 온도, 꽃 생산, 먹이 소비, 농약 노출과 거리 비용의 계수는 재현 가능한 가상 시나리오입니다. 3D의 넓은 경관도 측량 지도나 미터 단위의 20에이커 지도가 아닙니다. 화면의 최대 160마리 벌, 벌집 셀, 꽃, 채집 경로는 대표 시각화이지 개체별 행동 시뮬레이션이 아닙니다. **군집·먹이·날씨의 일별 수치는 모델 계산**, 화면 속 개별 벌의 움직임은 그 결과를 보여 주는 **시각적 해설**로 구분합니다.

데이터 연구실의 기본 군집 모델은 비교 가능성을 위해 먹이 저장을 추적하지 않습니다. 3D 생태 확장은 상대적 먹이 저장과 환경 피드백을 추가하므로 **같은 군집 파라미터라도 두 화면의 결과가 다를 수 있습니다.** 두 결과를 같은 모델의 동일 조건 검증값처럼 비교해서는 안 됩니다.

## 20에이커의 벌통 수는 어떻게 계산하나

선택한 개화 기간의 **하루 꽃 방문 수요**를 면적·꽃 밀도·꽃당 요구 방문량·자연 수분매개자 기여·예비율로 구성합니다. **한 벌통의 하루 방문 공급**은 채집벌 수·계절 활동·날씨·대상 작물 선택 비율·벌당 방문 횟수·유효 방문 비율로 계산합니다.

- **기간 전체의 방문량 하한:** 총수요 ÷ 한 벌통의 총공급을 올림. 다른 날의 초과 방문이 부족한 날을 보충할 수 있다는 느슨한 가정입니다.
- **날짜별 부족 기준:** 개화 기간 중 수요/공급 비율이 가장 큰 날을 충족하도록 올림. 공급이 0인 날은 벌통만 늘려 해결할 수 없습니다.

이 숫자는 **유효 꽃 방문 상당량을 충족시키는 시나리오별 벌통 수**입니다. 수정 성공률·수확량·현장 권장 벌통 수와 같지 않습니다. 벌통을 여러 개 놓았을 때 생기는 꽃 자원 경쟁, 벌통 배치, 실제 작물별 꽃 밀도는 아직 반영되지 않았습니다.

## 지금 확인할 수 있는 것

- **3D 세계:** 광역 경관/농장 시점, 벌통 단면, 구역별 날씨·꽃 자원, 벌의 대표 채집 장면. 재생·일시정지·날짜 이동과 `¼×`/`1×`/`4×`/`12×` 속도 조절을 지원합니다. `1×`는 실제 1초에 가상 6시간입니다.
- **환경 실험:** 연중 기후 유형, 개화 시기, 주변 서식지, 경관 연결, 물 접근성, 농약 노출 압력을 바꾸어 같은 날짜를 비교합니다. ‘비 많은 해’는 오늘의 비 스위치가 아니라 한 해의 습기 조건입니다.
- **데이터 연구실:** 단계별 개체군 그래프, 8개 변수의 국소 민감도, 고정 시드의 파라미터 시나리오, 개화기 수분 수요·공급 비교를 제공합니다.
- **결과 저장:** 일별 결과·민감도 CSV, 설정 JSON, 군집 그래프 SVG, 3D 시점 JSON, 비전문가용 1페이지 인쇄 화면을 제공합니다. 3D 시점 JSON과 연구실 설정 JSON은 서로 다른 형식입니다.

3D 화면에서는 드래그로 회전하고 휠로 확대합니다. `Space`는 재생/정지, `←`·`→`는 하루 이동, `I`는 벌통 내부, `E`는 환경 설정, `R`은 채집 경로 표시입니다. WebGL2가 없는 환경에서도 데이터 연구실은 사용할 수 있습니다.

## 검증 현황과 다음 연구

`npm test`는 발달 지연, 누적 생존율, 개체수 보존, 결정론적 재실행, 시간 제어, 공간 강수·눈·토양 수분, 먹이 피드백, 수분 계산 등을 검사합니다. **이는 코드와 수식의 일관성 검사이지 현장 예측력의 검증이 아닙니다.** 민감도 순위는 선택한 출력값·기준값·변화폭에 따라 달라지고, P10–P90 시나리오 범위는 통계적 신뢰구간이 아닙니다.

앞으로 대회 답안으로 만들 때의 우선순위는 다음과 같습니다.

1. **대상 지역과 작물 확정:** 실제 일별 기온·강수, 개화 시기, 꽃 밀도, 지형·토지피복 자료로 가상 시나리오를 대체하거나 비교합니다.
2. **군집 자료로 보정·외부 검증:** 성충·brood·먹이 관측에 맞춰 계수를 추정하고, 독립 기간의 오차를 제시합니다. 단순히 군집 크기를 20,000–80,000마리로 강제 제한하지 않습니다.
3. **민감도·불확실성 확장:** 변수 쌍의 상호작용, 기상·영양 불확실성, 서로 다른 성과 지표에서의 순위 변화를 확인합니다.
4. **수분 추정 검증:** 작물별 방문 요구량과 실제 벌통 운영 지침을 대조하고, 다수 벌통의 자원 경쟁과 꽃의 수용 기간을 검토합니다.
5. **최종 전달물 완성:** 핵심 그래프·한계·참고문헌을 정리해 25페이지 이내 보고서와 비전문가용 1페이지 자료를 마무리합니다.

현재 모델은 분봉, 여왕 교체, 바로아진드기·질병, 실제 농약 농도·독성곡선, 겨울벌의 생리 상태, 개별 벌의 비행 경로를 명시적으로 추적하지 않습니다. 더 많은 상태변수를 만드는 것보다 **가정과 자료의 근거를 확인하는 일**이 우선입니다.

## 로컬 실행

Node.js 22 이상이 필요합니다. 외부 패키지 설치, 빌드, API 키 없이 실행합니다.

```sh
git clone https://github.com/leejuhan-1214/HiMCM.git
cd HiMCM
npm start
```

3D 세계: [http://localhost:4173/HiMCM/](http://localhost:4173/HiMCM/) · 데이터 연구실: [http://localhost:4173/HiMCM/lab.html](http://localhost:4173/HiMCM/lab.html)

```sh
npm test
```

3D에는 WebGL2와 하드웨어 가속을 지원하는 브라우저가 필요합니다. 계산은 브라우저 안에서 실행됩니다.

## 저장소와 배포 구조

`src/model.js`는 단일 군집·민감도·수분 계산, `src/weather.js`는 공간 날씨, `src/world-state.js`는 날짜·3D 상태 연결, `src/world.js`는 장면 렌더링을 담당합니다. `tests/`는 수치·생태·날씨·시간 검사를, [METHODOLOGY.md](./METHODOLOGY.md)는 수식과 근거를 담습니다. 자세한 해석 없이 화면의 애니메이션만으로 과학적 결론을 내리지 않도록 문서를 함께 유지합니다.

GitHub Pages는 `main` 브랜치의 `/ (root)`에서 배포합니다. 정적 HTML·CSS·JavaScript 구조이며 개발용 `src/`와 Pages용 루트 실행 파일 사본을 **함께 갱신**해야 합니다. Pages 빌드 성공은 `npm test` 통과나 현장 모델 검증을 보장하지 않습니다.

핵심 구조 참고: [Khoury et al. 2011](https://doi.org/10.1371/journal.pone.0018491), [Khoury et al. 2013](https://doi.org/10.1371/journal.pone.0059084). 발달·생존 기준: [FAO 꿀벌 생물학](https://www.fao.org/4/x0083e/X0083E03.htm), [Fukuda & Sakagami 1968](https://doi.org/10.1007/BF02514731). 각 값의 적용 범위와 추가 출처는 [방법론 문서](./METHODOLOGY.md)에 정리했습니다.
