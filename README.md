# BeeLab

2022 HiMCM Problem A **The Need for Bees (and not just for honey)**를 위한 꿀벌 군집·수분 시뮬레이션입니다. 첫 화면은 계절·낮과 밤·벌통·꽃밭을 탐험하는 **3D 세계**입니다. 기존 **데이터 연구실**에서는 파라미터 비교, 민감도 분석, 보고서용 데이터·그래프 저장 기능을 계속 사용할 수 있습니다.

- 저장소: [leejuhan-1214/HiMCM](https://github.com/leejuhan-1214/HiMCM)
- GitHub Pages 배포 주소: [leejuhan-1214.github.io/HiMCM](https://leejuhan-1214.github.io/HiMCM/)
- 데이터 연구실 바로가기: [lab.html](https://leejuhan-1214.github.io/HiMCM/lab.html)
- 모델 수식·가정·출처·한계: [METHODOLOGY.md](./METHODOLOGY.md)

## 실행

Node.js 22 이상이 필요합니다. 외부 패키지 설치나 빌드 과정 없이 실행합니다.

```sh
git clone https://github.com/leejuhan-1214/HiMCM.git
cd HiMCM
npm start
```

[http://localhost:4173/HiMCM/](http://localhost:4173/HiMCM/)에서 3D 세계를, [http://localhost:4173/HiMCM/lab.html](http://localhost:4173/HiMCM/lab.html)에서 데이터 연구실을 확인합니다. 계산은 브라우저에서 실행되며 별도 API 키가 필요하지 않습니다. 3D 화면은 WebGL2 지원 브라우저와 하드웨어 가속이 필요합니다. 지원되지 않는 기기에서는 데이터 연구실을 이용할 수 있습니다.

```sh
npm test
```

테스트는 발달기간, 단계 생존율, 비음수 개체수, 흐름 보존, 영집단, 수분 공급의 한계, 연도를 넘는 개화기, 민감도 경계값과 난수 재현성을 확인합니다. 3D 시간 제어의 재생·정지·배속·연말 처리, 날짜 보간, 밤의 활동과 하루 수분 공급의 구분도 검사합니다. 자동 수치 검증과 별도로 실제 브라우저에서 카메라·터치·화면 크기별 렌더링을 확인해야 합니다.

## 3D 세계 사용법

- 마우스 드래그로 회전하고 휠로 확대합니다. 터치 기기에서는 한 손가락 회전과 두 손가락 확대를 사용합니다.
- 벌통을 선택하거나 `I`를 누르면 외벽을 연 **벌통 단면 관찰**이 열립니다. 육각 셀의 알·유충·봉개 번데기·저장 먹이 표본과 여왕·육아벌을 보면서 일별 산란·우화·채집 전환·사망 흐름을 함께 확인합니다.
- 귀환 중인 대표 채집벌의 뒷다리에는 노란 화분단이 나타나고, 방문된 꽃 중심은 주황색으로 바뀝니다. 꽃밭·벌을 선택하면 해당 시점의 수분·채집 설명이 열립니다.
- 재생 버튼 또는 `Space`로 시간을 멈춥니다. `←`·`→`는 하루 이동, 아래 날짜 막대는 원하는 시점으로 이동합니다. 입력창이나 버튼에 초점이 있을 때는 해당 요소의 기본 키 동작을 유지합니다.
- `¼×`, `1×`, `4×`, `12×`를 선택합니다. **1×는 실제 1초당 가상 6시간**입니다. 기본 시작 배속은 ¼×입니다. 반복을 켜지 않으면 연말에 멈춥니다.
- `I`로 벌통 내부, `E`로 환경 설정, `R`로 채집 경로를 켜고 끕니다. 날씨·군집 시나리오·개화일을 바꾸고 같은 날짜에서 비교합니다.
- 작은 화면에서는 기본 화면 품질을 낮춰 실행합니다. 환경 설정에서 품질을 직접 바꿀 수 있습니다. 동작 줄이기 설정을 사용하는 경우 시간을 정지한 상태로 시작합니다.
- ‘이 시간의 결과’에서 단계별 개체수, 그날의 방문 수요·공급과 필요 벌통 수를 확인하고 JSON을 저장합니다. 이 3D 스냅샷은 연구실의 실험 설정 JSON과 형식이 다르며, 연구실의 설정 불러오기 대상은 아닙니다.

3D의 벌은 실제 수만 마리를 대신하는 최대 160개의 대표 개체입니다. 벌집 셀도 단계 비율을 보여 주는 표본이며 실제 셀을 일대일 추적하지 않습니다. 지형·꽃·비행 경로는 이해를 돕기 위한 연출로, 실제 20에이커를 측량한 공간이나 개체별 행동 모델이 아닙니다. 군집 수치는 기존 일별 모델 사이를 보간하여 보여 줍니다. 시간을 되돌리는 것은 저장된 모델 궤적을 다시 보는 것이며 생물학적 역과정을 계산하는 것은 아닙니다.

선택한 맑음·비·건조는 비행 연출과 당일 수분 공급의 가정에 적용하며, 이후 군집 생존·영양 상태에는 되먹임하지 않습니다. 밤에는 보이는 비행 벌이 0이 되지만, 수분 공급 비율은 **하루 전체 기준**이므로 밤이라는 이유만으로 0이 되지 않습니다. 화면의 비율은 한 벌통의 수요 충족률이며 수정 성공률·수확량을 뜻하지 않습니다.

## 데이터 연구실 기능

- **단일 벌통:** 알 → 유충·번데기 → 내근벌 → 채집벌을 일별 연령 코호트로 추적하고 수벌도 별도로 계산합니다.
- **계절과 역할 전환:** 계절 산란, 육아 능력, 연령·사회적 억제에 따른 채집 전환, 계절별 사망확률을 조정합니다.
- **민감도와 불확실성:** 한 변수씩 변화시킨 국소 민감도와 고정 난수 시드의 파라미터 시나리오를 비교합니다. P10–P90 범위는 통계적 신뢰구간이 아닙니다.
- **20에이커 수분:** 개화기 날짜별 꽃 방문 수요와 채집벌 공급을 연결합니다. 전체 방문량으로 계산한 하한과 가장 부족한 날을 충족하는 벌통 수를 구분합니다.
- **재현·보고서:** 일별 결과와 민감도 CSV, 실험 설정 JSON 저장·불러오기, 설정 공유 URL, 군집 그래프 SVG 내보내기를 지원합니다.
- **비전문가 전달:** 한 페이지 블로그를 인쇄하거나 브라우저에서 PDF로 저장할 수 있습니다.

모든 개체수는 기대값이므로 소수가 가능합니다. 연구실의 일별 개체수는 하루 시작 시점의 값이고 사망·우화·전환량은 그 시점 직전 하루의 흐름입니다. 3D의 시간별 개체수는 이 일별 값의 선형 보간입니다.

## 모델의 범위

문헌에서 발달기간·생존율 예시와 모델 구조를 참고했지만, 계절·역할 전환·초기조건·영양·꽃 밀도 등의 설정에는 가정이 포함됩니다. **현장 자료에 보정하거나 독립 자료로 검증한 예측 모델이 아닙니다.**

기본 모델은 여왕 1마리와 관리되는 단일 벌통을 가정합니다. 먹이 저장량, 질병, 분봉, 공간 제한, 벌통 간 자원 경쟁은 직접 추적하지 않습니다. 예열 후에도 계절 주기가 수렴하지 않을 수 있으며 진단 경고를 함께 읽어야 합니다. 방문량은 실제 수정 성공률이나 수확량과 같지 않습니다.

핵심 참고자료는 [Khoury et al. 2011](https://doi.org/10.1371/journal.pone.0018491), [Khoury et al. 2013](https://doi.org/10.1371/journal.pone.0059084), [Fukuda & Sakagami 1968](https://doi.org/10.1007/BF02514731), [FAO 꿀벌 생물학](https://www.fao.org/4/x0083e/X0083E03.htm)입니다. 각 수치의 해석과 추가 출처는 방법론 문서와 사이트의 모델 설명에 정리했습니다.

웹사이트는 대회 보고서를 보완하는 실험 도구입니다. 최종 제출물은 문제에서 요구한 요약·목차·참고문헌 등을 포함하는 25페이지 이내 PDF로 별도 구성해야 합니다.

## GitHub Pages 배포

처음 한 번은 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다. 일반 워크플로 토큰은 최초 Pages 활성화를 수행할 수 없습니다.

이후 `main`에 변경사항을 올리면 [배포 워크플로](./.github/workflows/pages.yml)가 모델 테스트를 실행하고 통과한 버전을 공개합니다. Pages 설정 전에 실행되어 실패했다면 저장소 **Actions → Verify and deploy BeeLab → Re-run jobs**에서 다시 실행합니다. 배포 완료 여부와 주소는 워크플로의 `deploy` 작업에서 확인합니다.

정적 HTML·CSS·JavaScript ES 모듈 구조이며 CSS·스크립트 경로는 `/HiMCM/` 하위 경로에서도 동작하도록 상대 경로를 사용합니다. Three.js와 OrbitControls는 `vendor/`에 함께 제공하며 [Three.js 라이선스](./vendor/LICENSE-three.txt)를 포함합니다. 런타임에 3D 라이브러리를 CDN에서 가져오거나 API 키를 입력할 필요가 없습니다.
